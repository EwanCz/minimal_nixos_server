# minimal nixos server

Nix flake-based NixOS configuration for a personal server, deployed and updated remotely over SSH with [`nixos-anywhere`](https://github.com/nix-community/nixos-anywhere) and `nixos-rebuild`.

## What it does

- **Disk layout** — [`disko`](https://github.com/nix-community/disko) declaratively partitions and formats the disk: a GPT disk with an ESP boot partition and an LVM volume group holding the root filesystem (ext4).
- **Bootloader** — a custom `myConfig.boot` option (`modules/boot.nix`) picks between `LEGACY` and `UEFI` GRUB setups.
- **Base system** (`configuration.nix`) —
  - NetworkManager
  - Nix flakes enabled, `zethec` and `root` marked as trusted users, daily garbage collection
  - Two user accounts (`zethec`, `snorky`), both `wheel` + `docker`, SSH key auth only (password/root login disabled)
  - `tailscale` for remote networking, `docker` for containers
- **User environment** — [`home-manager`](https://github.com/nix-community/home-manager) (`modules/home-manager.nix`) manages the `zethec` user's packages (`btop`, `ncdu`, `eza`) and git configuration.
- **`hardware-configuration.nix`** — machine-specific hardware config, generated by `nixos-generate-config` (not meant to be hand-edited).

Everything is wired together in `flake.nix` as the `nixosConfigurations.server` output.

## Repo layout

```sh
.
├── flake.nix                 # flake inputs (nixpkgs, disko, home-manager) and the `server` nixosConfiguration
├── flake.lock
├── configuration.nix          # main system configuration
├── hardware-configuration.nix # generated hardware config
├── modules/
│   ├── boot.nix               # bootloader (LEGACY/UEFI) option
│   ├── disk-config.nix        # disko disk/partition/LVM layout
│   └── home-manager.nix       # home-manager config for the zethec user
└── script/
    ├── install_on.sh          # first-time install on a fresh target host
    └── deploy_on.sh           # push config updates to an already-installed host
```

## Usage

### Prerequisites

- Nix with flakes enabled on your local machine.
- SSH access to the target host as a user that can `sudo`.
  - `install_on.sh`: this is typically root access on a fresh boot medium or a nixos installer.
  - `deploy_on.sh`: an existing user with elevate/sudo rights. Recommand a trusted user as well.

### 1. First install (bare metal / fresh target)

```sh
./script/install_on.sh <user@target-ip>
```

This runs `nixos-anywhere`, which partitions the disk per `modules/disk-config.nix`, generates a fresh `hardware-configuration.nix` for the target, and installs NixOS from the `server` flake output — wiping the target disk in the process.

### 2. Deploy configuration changes

Once the server is installed, push any changes to `configuration.nix`/`modules/*` with:

```sh
./script/deploy_on.sh <user@target-ip>
```

This runs `nixos-rebuild switch --flake .#server --target-host <user@target-ip>`, building the new system closure and activating it on the remote host.

> [!Tip]
> Running this after a install might be needed in case home manager didn't init properly for zethec user.

## Notes

- SSH keys and hashed passwords for `zethec`/`snorky` are committed directly in `configuration.nix` — to replace before reusing this config for another server.
